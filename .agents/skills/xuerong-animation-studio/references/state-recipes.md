# 雪絨狀態動作配方

## 睡眠完整鏈

必須整段驗證：`idle -> yawning -> dozing -> collapsing -> sleeping -> waking -> idle`。

- `yawning`：從一般待機自然進入睏意，不突然縮放或蹲下。
- `dozing`：點頭連續、幅度小、沒有卡一下再點的節拍。閉眼後至少保持約 3 秒才第一次微睜；第 7 至 8 秒仍可有極少呼吸或髮尾動作，不能像影片停住。
- `collapsing`：身體慢慢下沉並向畫面右側倒下，最後頭位於畫面右側；禁止中途閃回站立、向左倒或整體漂移。
- `sleeping`：延續 collapsing 最後姿勢，頭保持在畫面右側。大多數時間閉眼且身體幾乎不動，隔較長時間才偶爾單眼偷瞄；不能閉眼後立刻睜眼。
- 閉眼節奏使用 `睜眼 -> ¾ 睜眼 -> 半睜 -> 全閉`，不要多加微瞇停格。
- `waking`：從 sleeping 的同一個右側頭位開始，單次自然起身，最後接回 idle；不能重播兩次或在結尾改變大小。

## 一般完成／打招呼

- 臉朝正面或明確看向使用者。
- 驚嘆號先出現，留一個可感知的反應停頓，再開始揮手。
- 只做一次完整招手段落，但揮動要有足夠停留，不要快速抽動。
- 愛心與驚嘆號放在不同側，避免視覺重疊。
- 結尾回到指定狀態，不能偷切成 typing 或重複首幀。

## 工作／打電腦

- 一般 `typing.webp` 與邊緣 `mini-working.webp` 都是循環動作，首尾接縫不可瞬移。
- 手、鍵盤、桌面和臉的視線方向要一致；不能出現左側破圖或白膜。
- 工作循環播放完一次後可保留約 133 ms 的短間隔再開始下一次，不能讓角色看起來停止太久。
- 邊緣打電腦在左右邊都必須面向螢幕內側。

## 拖曳與被抓起

- 除非使用者明確要求，不改目前核准的拖曳資產與速度。
- 被抓起時頭頂應形成受力感，表情可愛但不能讓角色比例突然縮小。
- 拖曳、釋放、回到一般模式的第一與最後姿勢要連續。

## 戳左／戳右

- 反應方向必須符合使用者戳擊所在的螢幕側，左右版本不能顛倒。
- 受力、頭髮和耳朵回彈要連續；回彈末段不可硬滑回原位。
- 兩側都以 idle 髮色、衣服色、畫質與人物尺度為基準，最多 5% 視覺尺度差。

## 雙擊愛心與煩躁

- `double-love`：愛心與撒嬌感清楚，但動作自然、不做作；從 idle 起始並平順回到 idle。
- `annoyed`：真的有一點不開心、鬧脾氣，但仍然可愛；表情與身體語言都要讀得出來，不能只加符號。
- 兩者都要特別檢查從 idle 切入及回到 idle 的色差、大小與位置跳動。

## 邊緣 Q 版

- 使用專為半身露出設計的動畫，不把一般模式等比縮小代替。
- 左右螢幕邊都要有正確鏡像；臉朝螢幕內側並保持可見。
- 右鍵進入迷你模式的完整移動約 900 ms：若距離足夠，可像開心的小女孩邊走邊自然自轉一圈；不是平面圖示原地旋轉。
- 拖到邊緣時允許最多遮住約半張臉，不要讓角色像撞到不可見牆。
- `mini-enter`、`mini-idle`、`mini-peek`、`mini-working`、`mini-happy`、`mini-alert` 與退出過場必須分別做左右邊合成驗證。
